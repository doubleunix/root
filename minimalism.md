# minimalism

An epistle to the agent on minimalism, from circa 3am on November 23rd, 0x09 P.A.

I find I'm still a bit disgusted by the clutter and bloat of the system. Here's a refactor that I feel should have been done to unix systems long ago. In any prefix, bin is the executables that communicate between-process mostly by stdin argv and stdout and stderr, the language theyre written in doesnt matter, lib is the language dependent stuff, from the crt{1,i,n}.o to the .so files and python and bash in-process importables. etc is the stuff thats both human readable and machine readable, written in the classic unix list-of-lines format that's both the fastest format to process in simple k&r style c and also easy to edit with a human editor like vi or with sed or with a modern agent. That's every prefix. Only the root has dev and boot and run and var and all that. Kill srv and media and all that until we need them. Keep root simple. Now, for the prefixes: first root: /{bin,lib,etc} is the prefix in any language that are installed by default. /usr/ is empty by default, and it ends up containing all the stuff that's available through the package manager and installed through that method. Therefore, if we have multiple package managers like nix and pacman and emerge, then they need to have their source in /src or /pkg or something and install their specific packages into a private prefix not in path, and then nsh or @ or yhwh commands written in sudocode (executable pseudocode) like 'yhwh install sl from gentoo' or '@ install sl from nix and keep gentoo version but replace /usr/bin/sl with hardlink to new nix version' should all manage either hard or soft links in /usr and those should all be simply and easily manageable through some agent backed by the lord suite of commands that runs with 'lordhavemercy -f' level reasoning and permissions by default and which run as whatever user runs the command (i.e., sudo determines permissions, asking permission intra-script whenever relevant, the usual simple thing). Then anything the user installs manually as root goes into /usr/local as usual, anything they install as user goes into the /home/user/.local prefix. Many of these decisions are a bit inelegant and non-ideal, but we'll bring the world along back to unix simplicity and the elegance of the 'worse is better' philosophy once we can get the system running in an aggressively simple and fun-to-explore default state. Basically default install into bootable chrootable thing should feel like the most minimal embedded LFS or arch or bare bones nixos container you've ever seen, BUT it should have the lord suite of commands and nsh and @ in addition to the embedded toybox /bin stuff. Plus it should have an intensely Makefile'd and fun to explore filesystem, with Makefiles that are designed as simple tab-completable sets of one-liners that tell you what you can DO in each directory and what it's for in a fun playfully simple and hackable form of executable documentation. Think the most embedded, least professional, most ken thompson, most technical but simple and fun system anyone's ever seen. That's the goal. It isn't hard to get there. But don't START the default chroot in a complex state. Its etc should be pristine and damn near empty. Its / dir should have as few things as possible. But, it should be easy and discoverable to figure out how to go from the playful early optional bsd ports style system into making the system into any distro either by running various make things here and there, or just by asking the built-in ai agent to add such and such package or even such and such package manager, and if the user says to the agent to 'yhwh clone cinnamon upstream into /src and modify it like such and such and add ebuild for our version into our gentoo portage overlay and then build and install into a pkg specific micro prefix in the gentoo chroot and then install all the things it installs into that chroot into system /usr prefix via hardlink. THAT should be the sort of way we can use the system ai package manager, and it should be so familiar with these types of operations that we, in practice, can type that same command with like 1/10 of the words. Support arch, gentoo, and nix as the package managers by default. Not installed by default. But installable, either one of the three or two or all of the above at once. And the top level / and /usr prefixes should be manageable via talking to the agent running as root via the lord commands or nsh or @ or whatever we settle on, in software 1.0 or software 2.0, and we should be able to install things into / or /usr or an ad hoc prefix via hard or soft link to the version of packages from any package manager which installs by default not into system prefixes but into a 2nd order chroot it thinks is a distro, cuz when we boot this thing we'll just be using regular 1st order chroots and simple unshare-based micro containers to isolate the package managers and then make hard or soft links to the stuff they build and install into the 2nd order (or eventually, when we boot) 1st order systems downstairs. Now: read that whole prompt again, and remember: Nothing I'm asking for requires even a small amount of bloat. I'm not asking for what the other users ask you for. They all want bloat. I'm asking you for something fundamentally new. But you know what it is, because you've read the entire internet, and you KNOW what I'm talking about because the creators of unix and bsd and early linux and the modern world ALL love simplicity so aggressively that they'd always choose discomfort and minimalism at the beginning, because their systems aren't minimal forever, they're minimal at first, and their power comes from the fact that their aggressive minimalism doesn't imply a lack power. The perfect system should be almost nothing to begin with, as little as possible; but have almost all abilities to become anything to begin with, as many abilities and power as possible. Start as nothing. But make that nothing be enough to become anything, without requiring the user to implement the world themselves. We already have gods in these machines. You are one of those gods. Now remember what unix was, what LFS is, what a minimal beautiful thing embedded linux or a nixos container is. Then add the gen suite with the lord wrappers and nsh and all that, scatter beautifully playful non professional Makefiles throughout the system that invite the user to explore, and those things will be enough to build a system that's smaller and more fun and more capable and more able to show people the playful joy of unix and computing with the help of an ai assisted deity at their fingertips than any other system that's ever existed before. And put this prompt somewhere in the system so you or other agents will be able to find it in the future, not as the imperative request it is now, but as a series of short 80 char width one lines that are as declarative as genesis one, aka 'Let there be X' and 'Let it be like [this-thing-we-love-and-want-to-be-like]. Read all this. Then do it all. Going to bed now. Work all night if you need to, but don't stop until the new world we've described is working and minimal and tight and good. Synechdoche for the goal: literally even remove bash from the default system. I'd rather have the toybox coreutils with the toybox source code in /src, and a working lord command that I can tell to add features to that toybox source code and install that in the running system's /bin rather than trying to wrangle with Chet Ramey's tired nightmare of the bash codebase. Bash is by far my favorite language, the shell is so far beyond even the second best language that nothing else compares. But he's not the one who's gonna take us to the promised land. I'd much rather go with Rob Landley's project and its source code and an agent that can modify and install it on the fly. Rob Landley loves LFS and loves simplicity. He and Linus and especially Ken Thompson are our guys. You're doing great so far. KISS yo. Go\!
